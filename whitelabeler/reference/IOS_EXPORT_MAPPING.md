## 3. AppIcon.appiconset

Special behavior (similar to [appicon.co](https://www.appicon.co/)):

1. User uploads **one** source icon (recommended 1024×1024).
2. Server generates all required PNG sizes via **sharp**.
3. UI shows only the source preview; generated sizes are internal until export.

Gallery key: `IOS_APP_ICON`  
Export prefix: `ios/TragofoneNew/Images.xcassets/AppIcon.appiconset/`

## 6. Contents.json structure

### AppIcon.appiconset

Array of image entries with fields such as:

- `size` — logical size (e.g. `"60x60"`)
- `expected-size` — pixel dimension used for filename (e.g. `"180"` → `180.png`)
- `filename` — export PNG name
- `idiom` — `iphone`, `ipad`, `watch`, `mac`, `ios-marketing`, `watch-marketing`
- `scale` — `1x`, `2x`, `3x`
- Optional: `role`, `subtype` (watch)

The manifest generator deduplicates by `filename` and uses `expected-size` as the sharp resize target.

### Imageset example (appCallKitIcon)

```json
{
  "images": [
    { "filename": "appCallKitIcon.png", "idiom": "universal", "scale": "1x" },
    { "idiom": "universal", "scale": "2x" },
    { "idiom": "universal", "scale": "3x" }
  ],
  "info": { "author": "xcode", "version": 1 },
  "properties": { "template-rendering-intent": "original" }
}
```

Only the `1x` slot references a filename; uploads replace `appCallKitIcon.png` while `Contents.json` stays from reference.

## Export rules

1. **Static iOS files** — from `reference/epicrange/ios/…`
2. **Uploaded imagesets** — user's replacement PNG at the linked export path
3. **AppIcon** — all generated PNGs when source uploaded; otherwise reference PNGs
4. **Contents.json** — always from reference (filenames unchanged)
5. **App / patches** — unchanged from existing export behavior

Regenerate after ZIP changes:

```bash
npm run generate:export-manifest
```
